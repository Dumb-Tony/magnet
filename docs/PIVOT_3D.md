# Active direction: rolling magnetic growth

> Historical first 3D experiment. The fixed-core districts implementation in DISTRICTS.md now takes precedence. The previous build is preserved in growth-first.html.

The user's request to replace delivery with Katamari-inspired growth and a 3D world supersedes the previous M1 delivery contract, including the 2D representation, 40-piece cap and one-file format. The earlier prototype is retained as `prototypes/m1/delivery-2d.html`. This is a bounded replacement experiment, not automatic progression to production or M2.

## Playable slice

One true perspective WebGL workshop, 103 collectible metal objects including the workbench. Begin with a 0.64 m diameter toy magnet on a 10×6 workbench. Collect bolts, cans and tools; use the sloping ramp or fall to the floor. Wheels, stools and lockers provide larger growth steps. At 3.6 m diameter, the bench becomes collectible; absorbing it ends the run with a retry screen. Movement stays brisk and increases modestly with size.

Every collected mesh stays attached to the rotating ball. Its original model size is retained as the shell expands. The renderer supplies actual 3D geometry, depth, perspective, lighting and shadows. Only the floating instructional signs use text sprites.

## Controls and rules

Movement is camera-relative with velocity easing, gravity and floor/table/ramp support. Rotation derives from distance traveled divided by radius. Camera follows smoothly, scales its distance with growth, and can be orbited with Q/E or dragging. No pointer lock is required.

Touch pickups are automatic when large enough; Space extends pull radius. Pickup size thresholds: cans require radius 0.48, tools 0.64, wheels 0.85, stools 1.05, lockers 1.35 and bench 1.8. Radius is `0.32 * cbrt(1 + mass / 1.2)`. No carried weight slowdown; speed is `4.8 + min(radius * 2.1, 4.5)` world units/second. Input easing is 9/s. The user's speed feedback informs this decision.

Shift sheds the latest five attachments and gives a small forward/upward burst. Ejected objects remain in the room, retain IDs and have a two-second pickup cooldown; burst cooldown is 1.4 seconds. There is surplus small scrap on the floor for early falls. The scripted run with deliberate shedding still reaches the workbench ending.

## Intentional prototype approximations

This pivot tests growth satisfaction, not the old compound-rigid-body hauling premise. The player uses a rolling spherical movement envelope and size-based obstacle/pickup bounds. Attached meshes are visible but do not each run independent rigid-body collision or alter inertia. Large uncollectible objects push the ball away with approximate bounds. The bench/ramp use a height surface and step-entry check. This is arcade motion, not a simulation of 103 articulated pieces. Shedding is not momentum conserving.

Procedural low-poly models, one fixed layout, no cars/city/world stages, no multiplayer or campaign. Camera wall avoidance, touch/gamepad controls, remapping and advanced accessibility settings are not implemented in this replacement experiment. WebGL is required and failure gets a visible message. Coverage is Chrome; browser/hardware compatibility remains a broader gate.

## Runtime and provenance

`index.html` + `growth.js` + local `vendor/three.min.js`; works from file:// without fetch or module imports. Three.js 0.160.1, MIT, pinned and bundled; license included. All models and sound are generated by project code. Fixed 1/120 s simulation, eight catch-up step cap, blur/visibility pause and cleared input. A namespaced optional fastest-run record uses guarded localStorage.

Renderer reference: https://threejs.org/manual/en/installation.html. Vendored source: https://cdn.jsdelivr.net/npm/three@0.160.1/build/three.min.js. The pinned classic-script bundle preserves direct offline opening; it is not a recommendation for a future production stack.
